# 简单需求

加载本 skill 后，发现需求其实涉及新页面、多个文件、设计图，或用户要看运行效果，停止执行本流程，改加载 dev-complex。

## 步骤

加载前这一轮如果已经读过要改的文件，并且 confirm 得到了 yes，直接从第 3 步写入，不要再定位和确认一次。

1. 定位要改的内容。用户已经用 `@` 指定文件时，直接 `read_file`。没指定时，用 `grep` 或 `glob` 找到文件再读。只读相关文件，不要扫整个仓库。
2. 调用 `confirm`，说明准备改哪个文件、改什么。用户否决就停，不要写文件。
3. 已有文件用 `edit_file`。`old_text` 必须和文件里的原文一致，并且只出现一次。只有新建文件时才用 `write_file`。
4. 再用 `read_file` 读改过的位置，确认片段已经写上。
5. 到此结束。不要调用 `debugger_page`，不要调用 `diff_pic`，也不要用 `bash` 去启动页面。

## 写文件失败时

`edit_file` 若提示找不到原文或出现多次，先重新 `read_file`，换一段更长、唯一的原文再试。不要改成整文件 `write_file` 来绕过。
