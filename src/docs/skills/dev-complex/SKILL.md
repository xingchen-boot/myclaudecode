# 复杂需求

加载本 skill 后，发现改动其实只是已有文件里的一两处，没有设计图，用户也没要求看效果，停止执行本流程，改加载 dev-simple。

## 步骤

加载前这一轮如果已经读过要改的文件，并且 confirm 得到了 yes，直接从第 3 步写入，不要再定位和确认一次。

1. 定位相关代码。用 `grep`、`glob` 找出要动的文件，再用 `read_file` 阅读。只读相关部分，不要扫整个仓库。
2. 调用 `confirm`，列出准备修改的文件，以及每个文件改什么。清单用几句话，不要先写一份 spec 文档。用户否决就停，不要写文件。
3. 用户同意后再写。已有文件用 `edit_file`，`old_text` 必须和原文一致且只出现一次。新建文件才用 `write_file`。
4. 写完用 `read_file` 读回改动处，检查有没有把相邻代码改坏。坏了就继续用 `edit_file` 修。
5. 只有用户要看效果，或已经给出可打开的页面地址时，才调用 `debugger_page`。没写过代码时程序会拒绝调试，这时先回到步骤 3。不要用 `bash` 启动开发服务器来代替 `debugger_page`。
6. 只有 `debugger_page` 已经返回截图路径，并且用户提供了设计图时，才调用 `diff_pic`。调试结果里有控制台报错时，先改代码再重新调试，不要对比设计图。

## 写文件失败时

`edit_file` 若提示找不到原文或出现多次，先重新 `read_file`，换一段更长、唯一的原文再试。不要改成整文件 `write_file` 来绕过。
